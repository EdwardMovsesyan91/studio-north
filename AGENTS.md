# Studio North agent guidance

- Milestones 5–8 authorize booking, protected administration and restricted synthetic demo operations. Preserve approved public layouts, themes, navigation/section motion, assets and data IDs. Do not add payments, customer accounts, real notifications, deployment or unrelated features.
- Keep one npm-workspace repository: React UI in `client`, Express/Mongoose API in `server`, contracts/decisions/progress in `docs`. Mongoose is the sole MongoDB data layer.
- Use strict TypeScript, readable components, explicit boundary validation and `unknown` rather than `any`. Use ESM with `.js` server-relative imports. Use npm and preserve the lockfile. New dependencies require a concrete need and verified compatibility.
- Preserve existing changes. Never commit/log secrets, `.env`, real personal information, generated output, screenshots or tool binaries. Never alter credentials implicitly. Licensed local photos require provenance in `docs/assets.md`; stock portrait subjects must not be identified as sample barbers.
- Run lint, typecheck, build and affected automated/runtime checks before claiming completion. Record actual results, skipped/blocked checks and limitations in `docs/progress.md`.
- Reuse semantic theme tokens and shared components. Preserve theme initialization/persistence, English fictional-demo disclosure, semantic HTML, visible focus, keyboard access, logical CSS properties and reduced motion. Keep `/design-system` outside the public layout.
- Header stays mounted across public route changes. Closed mobile links must be inert; preserve Escape/focus handling and shared desktop indicator. Preserve root stable gutter, `preventScroll` route focus and native scrolling. Do not intercept wheel/keyboard scrolling or set root overflow:hidden.
- SectionNavigator remains public Home-only, desktop/fine-pointer-only and tied to real sections. Decorative marks have no tab stops. Preserve native mobile/specimen/contrast-mode scrollbars and consistent hidden desktop public scrollbars.
- Portland, Oregon and `America/Los_Angeles` are the explicit fictional location/timezone. Store appointment instants in UTC; recurring hours are business-local minutes. Booking transactions require a replica set or compatible managed MongoDB.
- MongoDB is the permanent catalog/schedule source of truth. Do not reintroduce duplicate frontend service/barber/hour fixtures. Use TanStack Query for server state and React Hook Form/Zod for forms. Seed arrays are operator tooling, never runtime fallback data.
- Availability is advisory. Create/status/cancel/configuration/reset mutations must use the existing booking domain and shared transaction gate. Occupancy unique index and state must exist before writes. Cancellation releases blocks atomically; confirm/complete retain them. Never check then insert outside the transaction.
- Price values are integer cents. Preserve immutable appointment price/service-name snapshots. Schedule changes must reject invalid intervals/business bounds and protect upcoming/ongoing pending/confirmed appointments.
- Server authorization is mandatory for every admin endpoint. Use opaque expiring sessions, HttpOnly/SameSite/appropriate Secure cookies, exact Origin and CSRF validation, and rate-limited login. No registration/password-management or admin secrets in frontend code. Public reference lookup must never expose customer/contact/internal fields.
- Normal mode never permits visitor demo login or reset. Demo mode requires a strictly named, operator-designated isolated demo database. Replace visitor customer details with synthetic values before persistence. Reset only listed application collections transactionally; preserve credentials/sessions and rate counters. Never reset/drop `studio_north` or arbitrary databases.
- Development seed is insert-only and preserves edits/appointments. Integration tests use fresh exact guarded random names; cleanup only their own database. No destructive tests on normal development data. Public synthetic demo fixtures are the only persistent sample appointments.
- Keep every sample testimonial explicitly fictional and preserve gallery/portrait disclaimers. No fabricated reviews, analytics, claims or booking success; success follows committed server response only.
- Stop after the authorized milestone for review. Do not deploy automatically.
